01 · HamNavigator Map: map, stations and filters

Map displays station data from the connected digital decoder. Use My station for your location, Callsigns for the station list, Statistics for summaries and Settings for display options and integrations.

  1. Check your grid locator and UDP status. Wait for HamNavigator to decode a receive period.
  2. Zoom in or out. Select a station or grid square to examine available details.
  3. Check the band, mode and data-source filters. A filter can hide received stations even when the connection works.
  4. Use the right-click menu where available for station or map actions.

The map depends on sufficient position information in the received data. A callsign without a known grid locator may not produce a precise marker. Troubleshoot an empty map and an empty decode list separately.

03 · UDP with Map: 2237 → 2238

The standard connection on one PC is HamNavigator → HamNavigator Map → MY SHACK. The address 127.0.0.1 means this PC. The UDP port identifies the receiver; every stage must point to the correct receiver.

StageAddress / portPurpose
HamNavigatorSends to 127.0.0.1:2237Decodes, status and saved QSOs
HamNavigator MapReceives on 2237Displays stations and map
Map forwardingSends to 127.0.0.1:2238Forwards data to MY SHACK
MY SHACKReceives on 2238Displays messages and adds saved contacts
  1. In HamNavigator, open Settings / Options → Network Configuration → Page 1. Menu names can vary with the selected language.
  2. Under UDP Broadcast Settings, set Server to 127.0.0.1 and Port to 2237.
  3. Enable Enable Decoded Text and Enable Logged QSO ADIF. Use Reconnect if the connection needs to be re-established.
  4. In Map, open Settings → Station and connection. Check receive port 2237 and enable/check UDP forwarding to 127.0.0.1:2238.
  5. In MY SHACK, open My station, set UDP port 2238 and save. Open HamNavigator Digital and press Start receiving.

Keep Map open when using this chain. Do not assign both receivers to the same port. If you change MY SHACK's port, also change the forwarding destination port.

04 · Direct UDP without Map and an alternative log output

You can use MY SHACK without Map. HamNavigator then sends directly to MY SHACK's port, normally 127.0.0.1:2238.

  1. Check the port under My station.
  2. Set the same address and port in HamNavigator's regular UDP Broadcast Settings.
  3. Enable decoded text and Logged QSO ADIF, then start receiving in MY SHACK.

Simplified UDP Broadcast is an alternative if the regular output is already used elsewhere. Enable Logged QSO ADIF there and use MY SHACK's address and port. This output provides logged contacts, but not regular status and decoded text.

Choose a planned data route. Avoid a loop that forwards data back to an application's own input port. When changing a port during operation, stop and restart the receiver. MY SHACK accepts ports 1024–65535.

05 · Shared log and duplicates

The active PC log is hamnavigator.adi. Digital and MY SHACK use the same log; Map reads it as an application log. On Mobile, contacts are saved locally in the application and shared through Cloud. ADIF export suggests the same filename.

Duplicate checking compares callsign, UTC date and time together with band, mode, your station and activity references. A new contact with the same callsign a day later is retained. The same QSO from two devices should not become two contacts merely because internal IDs or frequency formatting differ.

Independent changes can be merged. Two different values in the same field may require a choice. Read the contact and timestamp before choosing. Make a copy before a large import or manual merge.

From PC version 1.9.15, Export ADIF suggests hamnavigator.adi. POTA and SOTA selections retain pota.adi and sota.adi. The exported file is a snapshot. Map should monitor the active shared log under App Log(s); a copy exported to Downloads is not updated automatically.

From PC version 1.9.16, the active log/hamnavigator.adi is the fixed Map source under App Log(s). Digital and MY SHACK write to and read from this file. Map reads new local changes automatically without uploading them again. Old radioassistent.adi export copies are removed from the application-log list, but the files are not deleted. Other logging applications’ sources are preserved. The internal data directory is still named Radioassistent for compatibility with existing logs, accounts and settings; do not rename it manually.

06 · Log services and shared passwords

  1. Open Map → Settings → Log integrations.
  2. Enter the service's username/email, password or API key. This is that service's account, not necessarily your HamNavigator password.
  3. Use its Test button and read the result. A successful connection test does not confirm that a particular QSO was uploaded.
  4. Enable Log? for services that should receive newly logged contacts. Connect?, Menu? and Startup? control other functions.
  5. Synchronize in MY SHACK. Another PC applies received Map settings after restarting.

Mobile shares QRZ, Club Log, eQSL and Cloudlog with Map. If fields are missing, open Menu → Log services → Retrieve usernames and passwords from Cloud. An older sign-in may ask once for your HamNavigator password to open the encrypted details. You do not need to sign out. If different populated accounts conflict, select the correct account.

Mobile's Wavelog settings and Club Log application key are local. Direct mobile uploads to LoTW, HRDLOG and HamCQ are unavailable. Prepare the TQSL application, station location and certificate locally on the signing PC.

07 · LoTW, TQSL and Station Name

  1. Prepare your valid callsign certificate and a station location in TQSL on this PC.
  2. Open Map → Settings → Log integrations → LoTW. Set TQSL Path to the installed tqsl.exe.
  3. Press Test TQSL. Select or enter Station Name exactly as the station location is named in TQSL, for example a name you gave it. It is not an arbitrary callsign.
  4. Login / Password is for your LoTW account. TQSL Password protects the certificate's private key if you set one. Leave it empty if the key does not require a password.
  5. Enable Log? for new contacts and check delivery status.

‘Logged to TQSL’ or ‘sent to LoTW’ is not a QSL confirmation. Check receipt/processing and any match at LoTW. An ordinary hamnavigator.adi is not a signed TQ8 file; use TQSL to sign it. A TQSL version shown in the test field only confirms that the application was found.

08 · Devices, deliveries and persistent error messages

Open Status and backup in MY SHACK or the mobile menu. It shows your devices, last contact/synchronization and pending changes. ‘Recently active’ means Cloud heard from the device in the last two minutes, not necessarily that someone is at the radio. The device list requires server 0.6.2.

Search for a callsign or UTC date in the delivery overview. New Map deliveries and Mobile's supported log services use shared Cloud coordination. A contact must be synchronized before delivery starts. When automatic Cloud synchronization is disabled, use Synchronize now.

  • Waiting / queued: delivery is not confirmed.
  • Confirmed saved: the service acknowledged it, or the contact's presence was checked manually.
  • Sent to LoTW: TQSL reported a successful upload; check processing and QSLs at LoTW.
  • Unknown / needs review: the connection may have failed after sending. Check this exact contact at the recipient before confirming it is present or allowing a retry.

Do not resend solely because a response is missing. Older contacts without acknowledgements may already exist at the service. Historical bulk upload is a separate task; Club Log's realtime queue is not for old contacts.

Error history survives restarts and groups repetitions. Copy troubleshooting information includes technical status and fixed error messages without passwords/API keys. If ‘Lost contact with the application’ appears, start HamNavigator from its shortcut again if the local background process has stopped. Do not delete log data to fix the connection.

09 · Mobile contacts on the PC map and remote desktop

Completed mobile contacts reach the PC log through Cloud when both devices synchronize. In Map, select a data view that includes the logbook and remove band/mode filters hiding the contact. The map needs position information to place a station.

Live decodes on the PC map come from a connected digital radio/UDP source. Synchronizing a QSO through Cloud does not transfer Mobile's audio, waterfall or every decode. External reception reports, such as PSK Reporter, may arrive later; they show that a receiver reported the signal, not that a QSO was completed.

With Chrome Remote Desktop, choose a suitable resolution/scale in the remote session and rearrange panels if they become cramped. A larger local monitor cannot provide more detail than the remote PC's rendered resolution. HamNavigator should normally run as a standard user so remote control can operate its windows.

10 · POTA and SOTA map: search, layers and markers

POTA / SOTA contains a map built into MY SHACK. This is a separate view of the park and summit registry, in addition to HamNavigator Map's station map.

  1. Select the POTA parks and/or SOTA summits layers.
  2. Enter a name or reference in the search box and press Search registry. Select a result to visit the location.
  3. Click a marker for its name, reference and details. A numbered marker represents several places; click to zoom in.
  4. Select Go to my station to find the area around your grid locator.
  5. Use Refresh map data to retrieve updated registry information. Check the status line for the result.

The location registry is included with the application. Background map tiles are downloaded, so a local reference may be available even when tiles fail to load. A marker indicates a registered coordinate, not a park boundary, an activator's current location or the whole activation zone. Check the relevant service when planning your trip.

11 · Backup and recovery

Open Status and backup for local Cloud backups associated with your account. These copies are on the PC; a Cloud account does not replace your own backups.

  1. Select a copy and review its date, contact count and how many are missing from the current log.
  2. Review before confirming recovery. The application makes a local copy first.
  3. Only missing contacts are added. Current contacts and newer changes are preserved. This contact recovery does not replace current settings.
  4. Check the result and synchronize with your other devices.

Under My station, you can also save a JSON backup and preview a selected file before importing. Recovery adds missing contacts and favourite repeaters. It does not automatically upload old contacts to log services.

On a new PC, install HamNavigator, sign in with the same account and synchronize. Restart the application to apply received application/panel settings. Check radio drivers, USB audio and local ports. The TQSL application, certificate and station location must be available on the PC that signs uploads.

12 · Update PC, Map and Mobile

  1. Stop radio operation. Press Update at the top of the Windows window.
  2. Read the installed and available versions. Select Update now and wait for download and file verification.
  3. The installer asks HamNavigator, Digital and Map to save and close. Complete any open dialogs. If closing fails, resolve the cause and try again.
  4. Complete installation. MY SHACK opens without automatically resuming radio operation.
  5. Check the version and start receiving when the radio setup is ready.

The PC package also updates Digital and Map. Map does not need a separate HamNavigator update alongside it. On Mobile, use Menu → Update app. Install the APK over the existing application with the same signature; do not uninstall first.

New device/delivery overview functions require private Cloud server 0.6.2 or later. The server owner uses Update server on the server PC. The account, certificate and saved connection are normally retained. Client releases are published on GitHub; server files are distributed privately. Refresh map data updates only the POTA/SOTA registry.

The Update button finds published stable PC releases on GitHub that include the installer. The download is verified with SHA-256 before installation starts. “You have the latest version” refers to the latest published PC release. Source code changes alone are not an installable update.

13 · Application log, local files and troubleshooting

Under Settings → Log integrations, App Log(s) lists files Map monitors from logging applications. Check that the active hamnavigator.adi is included. Use Read local log if a saved contact has not appeared. Extra files under Local File(s) are separate data sources; an old desktop copy does not automatically become the active shared log.

Import log reads a selected file into Map. Check MY SHACK before assuming a Map import is in the shared Cloud log. Use MY SHACK's Import ADIF to add contacts to the shared log.

An empty background map may be caused by map tiles/network access; missing stations by UDP or filters; missing QSOs by the wrong log file or an incomplete/unsaved contact. Change log accounts under Log integrations and the application connection under Station and connection.
