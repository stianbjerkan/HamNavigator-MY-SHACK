01 · First startup and sign-in

HamNavigator for PC brings together MY SHACK, Digital and Map. MY SHACK manages your account, shared log and Cloud; Digital handles the radio, waterfall and decoding; Map displays stations and log integrations.

  1. Start HamNavigator MY SHACK. Select Sign in or Create account under Account and Cloud.
  2. Use the same email address and HamNavigator password on your PCs and mobile device. New passwords must contain 12–256 characters. Complete email verification if requested.
  3. New installations connect automatically to the public Cloud address. Advanced: custom server is for a separate server setup; ordinary users need neither the server administration page nor a client certificate file.
  4. Open My station, check your callsign and grid locator, then select Save station settings.
  5. Check audio, radio/CAT, PTT and UTC in Digital. Start receiving before transmitting.

Select Språk / Language to choose Norwegian, English or Swedish. MY SHACK changes immediately. Restart HN to apply the choice to its Windows controls, Digital and Map. Stop transmitting before restarting. The language is remembered on this device; changing it does not alter contacts, passwords or radio settings.

A saved sign-in allows local contacts to be retained during a temporary network outage. Signing in and online services require a connection. The local user guide can be read offline. Radio drivers and physical audio/port selections must suit each PC.

02 · Panels, locking and 3 × 2

Select the number of Panels at the top of the Windows window, from 1 to 24. ＋ New panel adds one. Select each panel's content from its menu.

  1. Select Side by side, Stacked vertically or Grid layout, then use Arrange panels.
  2. Select 3 × 2 – six panels for three columns and two rows.
  3. Free layout lets you move title bars and drag edges.
  4. Press Lock panels when the layout is ready. Use Unlock panels before moving or changing it again. Locking does not stop the radio.
  5. Detach window moves an application out of its panel; Open … here brings it back.

The layout is remembered and can be shared with the same Cloud account. A received layout is applied at the next startup; different screen sizes may require local adjustments. Selecting one application in multiple panels does not create independent radios.

When closing, Digital and Map are allowed to save and exit normally. If a dialog prevents closing, complete it and try again. Other applications you added yourself may continue running outside the panel.

03 · Add applications and select modules

＋ Add application … in the Windows toolbar lets you select an .exe file. The application becomes available as panel content. Embedding requires a regular main window; splash screens, dialogs and applications with unusual window types may remain outside the panel.

Select modules inside MY SHACK controls which pages and overview cards are shown. This is separate from the number of Windows panels. Press Save module selection to apply your choice. UTC clock only gives a simple overview; Select all restores the modules. User guide, Overview and My station remain available.

Hiding a module does not delete data. Active connections may continue running. The Callsign listener stops when its module is hidden. If a button is missing, check the module selection before changing the installation.

04 · UTC, local time and the correct date

The overview clock displays UTC and local time. QSO times and activation dates use UTC. A new UTC day may begin at a different time from the local calendar day.

  1. Check the date, time and time synchronization in Windows.
  2. Compare the application's UTC display with a time source you trust.
  3. For digital modes with fixed periods, check the clock if signals are clear but do not decode or appear at the wrong point in the period.

The UTC widget displays the PC clock. It does not adjust or synchronize Windows time. Changing the time zone to correct the displayed time is not the same as correcting an inaccurate system clock.

05 · HamNavigator: audio, radio and digital decoding

HamNavigator handles audio input, the waterfall, decoding, messages and the radio connection. MY SHACK receives status, decodes and saved contacts over UDP. An empty MY SHACK list therefore does not necessarily mean the digital decoder has stopped.

  1. Open HamNavigator in a panel. Select the required Mode and Band in Digital.
  2. Open the audio and radio settings. Select the radio's receive audio as input and the correct transmit output. Audio device names are supplied by Windows and the radio driver.
  3. Check that the waterfall shows signals and that the audio level is sufficient without clipping. Observe a complete receive period.
  4. Set your callsign, grid locator, radio/CAT and PTT as required in Digital. Use the radio model's instructions for the port, baud rate and audio/data mode.
  5. Confirm that received messages appear in HamNavigator before troubleshooting transfer to Map or MY SHACK.

CAT, PTT, automatic transmission and message sequences are controlled in Digital. MY SHACK's UDP receiver sends no radio or transmitter commands. Starting a panel does not verify the radio's physical setup.

06 · UDP with Map: 2237 → 2238

The standard connection on one PC is HamNavigator → HamNavigator Map → MY SHACK. The address 127.0.0.1 means this PC. The UDP port identifies the receiver; every stage must point to the correct receiver.

StageAddress / portPurpose
HamNavigatorSends to 127.0.0.1:2237Decodes, status and saved QSOs
HamNavigator MapReceives on 2237Displays stations and map
Map forwardingSends to 127.0.0.1:2238Forwards data to MY SHACK
MY SHACKReceives on 2238Displays messages and adds saved contacts
  1. In HamNavigator, open Settings / Options → Network Configuration → Page 1. Menu names can vary with the selected language.
  2. Under UDP Broadcast Settings, set Server to 127.0.0.1 and Port to 2237.
  3. Enable Enable Decoded Text and Enable Logged QSO ADIF. Use Reconnect if the connection needs to be re-established.
  4. In Map, open Settings → Station and connection. Check receive port 2237 and enable/check UDP forwarding to 127.0.0.1:2238.
  5. In MY SHACK, open My station, set UDP port 2238 and save. Open HamNavigator Digital and press Start receiving.

Keep Map open when using this chain. Do not assign both receivers to the same port. If you change MY SHACK's port, also change the forwarding destination port.

07 · Direct UDP without Map and an alternative log output

You can use MY SHACK without Map. HamNavigator then sends directly to MY SHACK's port, normally 127.0.0.1:2238.

  1. Check the port under My station.
  2. Set the same address and port in HamNavigator's regular UDP Broadcast Settings.
  3. Enable decoded text and Logged QSO ADIF, then start receiving in MY SHACK.

Simplified UDP Broadcast is an alternative if the regular output is already used elsewhere. Enable Logged QSO ADIF there and use MY SHACK's address and port. This output provides logged contacts, but not regular status and decoded text.

Choose a planned data route. Avoid a loop that forwards data back to an application's own input port. When changing a port during operation, stop and restart the receiver. MY SHACK accepts ports 1024–65535.

08 · From a decode to a saved contact

A decoded message, a map marker and a saved QSO are different things. The decode list shows received messages. A contact is transferred to MY SHACK when it is saved in HamNavigator and its log message is sent over UDP.

  1. Follow the contact in Digital and check the callsign, band/frequency, mode and report.
  2. Save the QSO in HamNavigator.
  3. Open MY SHACK's Logbook and check that the contact appears with the correct UTC time.
  4. Correct errors with Edit. The shared log is used by MY SHACK and Digital; corrections are not automatically applied to separate third-party logs or online services.

If only QSOs appear, the Simplified output may be in use. If decodes appear but contacts do not, check Logged QSO ADIF and that the QSO was actually saved. Use ADIF import for an older log; starting UDP does not automatically transfer historical contacts.

09 · HamNavigator Map: map, stations and filters

Map displays station data from the connected digital decoder. Use My station for your location, Callsigns for the station list, Statistics for summaries and Settings for display options and integrations.

  1. Check your grid locator and UDP status. Wait for HamNavigator to decode a receive period.
  2. Zoom in or out. Select a station or grid square to examine available details.
  3. Check the band, mode and data-source filters. A filter can hide received stations even when the connection works.
  4. Use the right-click menu where available for station or map actions.

The map depends on sufficient position information in the received data. A callsign without a known grid locator may not produce a precise marker. Troubleshoot an empty map and an empty decode list separately.

11 · POTA and SOTA map: search, layers and markers

POTA / SOTA contains a map built into MY SHACK. This is a separate view of the park and summit registry, in addition to HamNavigator Map's station map.

  1. Select the POTA parks and/or SOTA summits layers.
  2. Enter a name or reference in the search box and press Search registry. Select a result to visit the location.
  3. Click a marker for its name, reference and details. A numbered marker represents several places; click to zoom in.
  4. Select Go to my station to find the area around your grid locator.
  5. Use Refresh map data to retrieve updated registry information. Check the status line for the result.

The location registry is included with the application. Background map tiles are downloaded, so a local reference may be available even when tiles fail to load. A marker indicates a registered coordinate, not a park boundary, an activator's current location or the whole activation zone. Check the relevant service when planning your trip.

12 · Your POTA/SOTA activation, step by step

  1. Set your trip callsign and grid locator under My station and save.
  2. Find the location on the POTA/SOTA map. Select Use as my activation, or enter your park/summit reference under My activation.
  3. Check the reference before selecting Start activation. The application checks the text format, but manually entered references are not automatically checked against the entire registry.
  4. Log new contacts manually or from HamNavigator. Check that your reference is included in the log.
  5. Select End activation when finished or moving to another location.
  6. Filter the activation log by program, activator role, your reference and UTC date. Export ADIF and submit it to the appropriate service.

An activation applies to new contacts from its start time until the end of that UTC day. It does not change earlier contacts. Start a new activation after UTC midnight if you continue. One POTA park and one SOTA summit can be active at the same time.

The station details at activation start are defaults for new contacts without those fields. When moving or changing callsign, end the activation, correct your station settings and start again. Always check contacts before exporting.

13 · Hunter log, park-to-park and reference fields

Your reference and the other station's reference belong in separate fields. On the map, use Log a contact with this location when the location belongs to the other station. Check its callsign yourself in the contact window.

A park-to-park QSO can include both your park and the other station's park. Do not change your activation to the other station's location. To find contacts you hunted, select Hunter / chaser in the log filter. Select Activator for contacts with your own reference.

14 · Spotting and submitting to POTA/SOTA

At the top of the POTA/SOTA page, POTA – open spotting and SOTA – open SOTAwatch open those services in your browser. Sign in there if needed and use the service's new spot or planned activation function.

Check the callsign, reference, frequency, mode and comment before publishing. MY SHACK does not automatically publish a spot when you start an activation or save a contact.

ADIF export downloads a local file. It is not an automatic submission either. Open POTA or SOTA, follow its upload process and check the import result. The application does not determine whether an activation meets a service's requirements or earns points.

15 · Logbook, search and corrections

  1. Select Logbook → New contact, or use quick logging on the overview.
  2. Enter the callsign, UTC date and time, mode, band/frequency and reports. Enter frequency in MHz where the field is labelled MHz.
  3. Check the grid locator and any POTA/SOTA references before saving.
  4. Find the contact in the logbook. Clear the search and mode filter if it is not shown.

MY SHACK and Digital use the shared log hamnavigator.adi. A decoded CQ is not a completed contact. Edit updates the selected contact; Delete requires confirmation. External log services are not automatically updated with deletions. Check and back up before major changes.

The same station on a different date or at a different UTC time is a new contact. See ‘Shared log and duplicates’ for how synchronization handles matching contacts.

16 · Import and export ADIF

ADIF transfers QSOs between logging applications. In Logbook, select Import ADIF and choose an .adi, .adif or text file. The maximum import size is 15 MB.

  1. Make a backup before a large import.
  2. Import the file and read the result: new contacts, duplicates skipped and invalid contacts.
  3. Review errors and representative QSOs before using the entire log further.

Export ADIF in the regular logbook exports the log; the table's search is not a separate export selection. For a limited POTA/SOTA selection, use the export and filters on the POTA/SOTA page.

Exported ADIF uses ASCII. Norwegian characters in free text are simplified. Use a JSON backup to preserve all text. Import can skip duplicates, but does not automatically merge every conflicting correction across multiple logs.

17 · Backup and recovery

Open Status and backup for local Cloud backups associated with your account. These copies are on the PC; a Cloud account does not replace your own backups.

  1. Select a copy and review its date, contact count and how many are missing from the current log.
  2. Review before confirming recovery. The application makes a local copy first.
  3. Only missing contacts are added. Current contacts and newer changes are preserved. This contact recovery does not replace current settings.
  4. Check the result and synchronize with your other devices.

Under My station, you can also save a JSON backup and preview a selected file before importing. Recovery adds missing contacts and favourite repeaters. It does not automatically upload old contacts to log services.

On a new PC, install HamNavigator, sign in with the same account and synchronize. Restart the application to apply received application/panel settings. Check radio drivers, USB audio and local ports. The TQSL application, certificate and station location must be available on the PC that signs uploads.

18 · Log and settings locations

Enter these environment-variable paths in the Windows File Explorer address bar. They apply to the standard profile; a custom data directory may be elsewhere.

  • %APPDATA%\Radioassistent\log\hamnavigator.adi: the shared log used by MY SHACK and Digital.
  • %APPDATA%\Radioassistent: MY SHACK data and panel layout.
  • %APPDATA%\Radioassistent\cloud\backups: local encrypted Cloud backups.
  • %APPDATA%\HamNavigator-Map: Map's user profile; log integrations are in the profile settings.
  • release\HamNavigator\settings inside the installation directory: Digital settings. Older log files under Digital are not the active shared log.
  • %LOCALAPPDATA%\HamNavigator\updates: downloaded PC updates.
  • %APPDATA%\Radioassistent\ui-language.json: the local Norwegian/English/Swedish interface preference.

Find the installation directory using ‘Open file location’ on the shortcut. Keep older logs and migration copies until you have checked contact counts. Do not delete data directories to update the application.

19 · Callsign listener: audio source and sensitivity

The listener uses local speech recognition for spoken callsigns on SSB, FM and AM. It is not a CW, FT8 or FT4 decoder.

  1. Open Callsign listener and select Find audio sources.
  2. Select the radio's USB/line input. PC audio can capture playback on the PC, while a microphone can listen beside the radio speaker.
  3. Select the speech language: English/international radio, Norwegian or automatic.
  4. Start with an audio threshold of −48 dBFS and a speech filter of 220–3400 Hz. Choose −60 for weaker audio or −36/−24 for less sensitive detection.
  5. Press Start listening and watch the level meter. Lower the input level if it clips. Stop listening before changing the audio source or sensitivity.

No audio source starts automatically. The speech model must be ready before recording can start. Listening stops when the module is hidden or the listener window loses contact with the application for more than 15 seconds. Changing pages is not a general stop button; use Stop listening when finished. Speech recognition language is separate from the interface language.

20 · Review suggestions, play audio and test a WAV file

Suggestions are a listening aid. Noise and multiple voices can produce incorrect letters and numbers; repetition in overlapping audio segments is not independent confirmation.

  1. Select a possible callsign and read the text under What the application heard.
  2. Use Play to check the audio segment. If listening is active, it stops first so playback is not transcribed again.
  3. Correct the callsign before selecting Use in new contact. The Logbook module must be enabled.
  4. Complete and save the contact in its window. A suggestion is not automatically a logged QSO.

Try a WAV file uses a local recording: 16-bit PCM, mono or stereo, at most 60 seconds and smaller than 12 MB. Up to 30 audio segments are retained temporarily in memory. Clear session removes its audio and text; this is not a permanent audio archive.

21 · HF & DX: cluster, filters and band overview

  1. Enter the DX cluster hostname, port and your callsign under My station.
  2. Open HF & DX and select Connect. Your callsign is sent as the sign-in to the selected Telnet cluster.
  3. Filter by band and text. For alerts, enter callsign prefixes to watch in the station settings.
  4. Use Disconnect to stop the connection.

Prefix alerts match text; they are not a complete DXCC entity database. An empty filtered list does not mean the cluster is disconnected; read its connection status. Host and port changes apply at the next connection.

Solar data and band tips are guidance. Consider the measurement time and recent spots alongside what you actually hear. A spot indicates reported activity, not a guaranteed path from your station. The overview does not automatically tune the radio to the displayed frequency.

22 · VHF/UHF, grid locator, antenna bearing and notes

VHF / UHF holds your favourite repeaters. Check frequency, offset, access tone and mode against the repeater's information before programming your radio. The favourites list does not automatically program the radio.

Tools calculates distance and bearing between Maidenhead locators of 4, 6 or 8 characters. It uses grid-square centres and the shortest route along the Earth's surface. Bearing is measured from true north. The coordinate tool uses positive numbers for north and east.

The antenna-length tool gives starting dimensions for a half-wave dipole and quarter-wave vertical. The dipole value is total length, not the length of each leg. Enter frequency in MHz; the shortening factor adjusts the starting estimate. Adjust using measurements in the actual installation.

Under Radio help, save your own station notes. Record the radio model, antenna, audio device name, CAT port, baud rate, PTT method and UDP ports. This makes a working setup easier to reproduce.

23 · Update PC, Map and Mobile

  1. Stop radio operation. Press Update at the top of the Windows window.
  2. Read the installed and available versions. Select Update now and wait for download and file verification.
  3. The installer asks HamNavigator, Digital and Map to save and close. Complete any open dialogs. If closing fails, resolve the cause and try again.
  4. Complete installation. MY SHACK opens without automatically resuming radio operation.
  5. Check the version and start receiving when the radio setup is ready.

The PC package also updates Digital and Map. Map does not need a separate HamNavigator update alongside it. On Mobile, use Menu → Update app. Install the APK over the existing application with the same signature; do not uninstall first.

New device/delivery overview functions require private Cloud server 0.6.2 or later. The server owner uses Update server on the server PC. The account, certificate and saved connection are normally retained. Client releases are published on GitHub; server files are distributed privately. Refresh map data updates only the POTA/SOTA registry.

The Update button finds published stable PC releases on GitHub that include the installer. The download is verified with SHA-256 before installation starts. “You have the latest version” refers to the latest published PC release. Source code changes alone are not an installable update.

25 · Troubleshooting: panels, audio, map data and updates

  • The application opens outside its panel: finish startup and any dialogs, then select ‘Open … here’ again. Check the selected .exe. Settings dialogs may normally be separate windows.
  • The listener has no audio source: check that Windows sees the device, connect the radio and select ‘Find audio sources’ again. Select the receive input rather than an unused microphone.
  • Poor listener suggestions: check the speech language, listen to the recording and adjust audio level and threshold. Clipping and overlapping voices cannot be corrected by trusting the suggestion more.
  • Empty background map: check the internet connection. Try reference search to distinguish registry data from online map tiles.
  • Activation contacts lack a reference: check that activation started before the QSO's UTC time and that the UTC day has not changed.
  • No Update button: check the Windows toolbar and confirm version 1.4.0 or later. It is not a browser button inside an individual module.
  • Download fails: check the network and free disk space. If GitHub limits requests, wait and try again. Download again after a checksum mismatch.
  • Some HN controls still use the previous language: save the choice under Språk / Language and restart HN after stopping transmission. Windows-provided file dialogs follow Windows settings. User content remains in its original language.

When reporting a problem, include the version, page or panel, exact steps and error message. Include relevant ports and audio device names. Use a copy of the log when investigating import problems.

26 · Glossary and suggested workflow

ADIF
A file format for transferring amateur radio contacts between logging applications.
CAT
Computer control and status exchange between a radio and application.
PTT / RX / TX
Keying the transmitter / reception / transmission.
QSO / CQ / DX
A radio contact / a general call / a distant contact or station.
Locator / grid
A Maidenhead grid square indicating a geographic area.
UDP / forwarding
Data messages sent to an address and port / an application passing received data onwards.
UTC
The common time reference for clocks, QSO logs and activation dates.
Activator / hunter / chaser
The station at a park or summit / a station contacting the activator.
dBFS
Audio level relative to digital full scale; 0 dBFS is the upper limit.

Before operating: check the clock, station, audio, ports and map filters. Start an activation if relevant. While operating: verify heard callsigns and saved QSOs. After operating: end activation and listening, check the log, export if needed and make a backup.

27 · Account and Cloud across devices

Use the same HamNavigator account on your PCs and tablet. Open Account and Cloud, sign in and select Synchronize now or automatic synchronization. PC offers automatic synchronization every 10 seconds. Mobile synchronizes when opened, every 30 seconds while in use, and after new radio contacts.

Network outages and a closed application can delay transfer. Contacts are saved locally first. ‘In Cloud’ means the contact is synchronized, not that QRZ or LoTW has received it. Check your other devices under Status and backup.

PCs share the log, station details, module selection, panel layout and encrypted application settings. Received Digital/Map settings apply at the next startup. USB devices, local file paths and active radio transmission are not transferred as a ready-made machine configuration. For a genuine settings conflict, choose the version in Account and Cloud before restarting. Empty fields should not reset another device's account.

Use the account recovery process if you forget the password. Keep the recovery key from Account and Cloud; it is needed for encrypted settings if the account password is forgotten. Do not include the key in a problem report.

28 · Shared log and duplicates

The active PC log is hamnavigator.adi. Digital and MY SHACK use the same log; Map reads it as an application log. On Mobile, contacts are saved locally in the application and shared through Cloud. ADIF export suggests the same filename.

Duplicate checking compares callsign, UTC date and time together with band, mode, your station and activity references. A new contact with the same callsign a day later is retained. The same QSO from two devices should not become two contacts merely because internal IDs or frequency formatting differ.

Independent changes can be merged. Two different values in the same field may require a choice. Read the contact and timestamp before choosing. Make a copy before a large import or manual merge.

From PC version 1.9.15, Export ADIF suggests hamnavigator.adi. POTA and SOTA selections retain pota.adi and sota.adi. The exported file is a snapshot. Map should monitor the active shared log under App Log(s); a copy exported to Downloads is not updated automatically.

From PC version 1.9.16, the active log/hamnavigator.adi is the fixed Map source under App Log(s). Digital and MY SHACK write to and read from this file. Map reads new local changes automatically without uploading them again. Old radioassistent.adi export copies are removed from the application-log list, but the files are not deleted. Other logging applications’ sources are preserved. The internal data directory is still named Radioassistent for compatibility with existing logs, accounts and settings; do not rename it manually.

29 · Log services and shared passwords

  1. Open Map → Settings → Log integrations.
  2. Enter the service's username/email, password or API key. This is that service's account, not necessarily your HamNavigator password.
  3. Use its Test button and read the result. A successful connection test does not confirm that a particular QSO was uploaded.
  4. Enable Log? for services that should receive newly logged contacts. Connect?, Menu? and Startup? control other functions.
  5. Synchronize in MY SHACK. Another PC applies received Map settings after restarting.

Mobile shares QRZ, Club Log, eQSL and Cloudlog with Map. If fields are missing, open Menu → Log services → Retrieve usernames and passwords from Cloud. An older sign-in may ask once for your HamNavigator password to open the encrypted details. You do not need to sign out. If different populated accounts conflict, select the correct account.

Mobile's Wavelog settings and Club Log application key are local. Direct mobile uploads to LoTW, HRDLOG and HamCQ are unavailable. Prepare the TQSL application, station location and certificate locally on the signing PC.

30 · LoTW, TQSL and Station Name

  1. Prepare your valid callsign certificate and a station location in TQSL on this PC.
  2. Open Map → Settings → Log integrations → LoTW. Set TQSL Path to the installed tqsl.exe.
  3. Press Test TQSL. Select or enter Station Name exactly as the station location is named in TQSL, for example a name you gave it. It is not an arbitrary callsign.
  4. Login / Password is for your LoTW account. TQSL Password protects the certificate's private key if you set one. Leave it empty if the key does not require a password.
  5. Enable Log? for new contacts and check delivery status.

‘Logged to TQSL’ or ‘sent to LoTW’ is not a QSL confirmation. Check receipt/processing and any match at LoTW. An ordinary hamnavigator.adi is not a signed TQ8 file; use TQSL to sign it. A TQSL version shown in the test field only confirms that the application was found.

31 · Devices, deliveries and persistent error messages

Open Status and backup in MY SHACK or the mobile menu. It shows your devices, last contact/synchronization and pending changes. ‘Recently active’ means Cloud heard from the device in the last two minutes, not necessarily that someone is at the radio. The device list requires server 0.6.2.

Search for a callsign or UTC date in the delivery overview. New Map deliveries and Mobile's supported log services use shared Cloud coordination. A contact must be synchronized before delivery starts. When automatic Cloud synchronization is disabled, use Synchronize now.

  • Waiting / queued: delivery is not confirmed.
  • Confirmed saved: the service acknowledged it, or the contact's presence was checked manually.
  • Sent to LoTW: TQSL reported a successful upload; check processing and QSLs at LoTW.
  • Unknown / needs review: the connection may have failed after sending. Check this exact contact at the recipient before confirming it is present or allowing a retry.

Do not resend solely because a response is missing. Older contacts without acknowledgements may already exist at the service. Historical bulk upload is a separate task; Club Log's realtime queue is not for old contacts.

Error history survives restarts and groups repetitions. Copy troubleshooting information includes technical status and fixed error messages without passwords/API keys. If ‘Lost contact with the application’ appears, start HamNavigator from its shortcut again if the local background process has stopped. Do not delete log data to fix the connection.

32 · Waterfall, RX/TX and Hz

The waterfall shows the audio actually received from the radio. An empty frequency range is not necessarily a display fault. The radio's audio filter may limit signals even when the application displays a wider Hz range.

  1. Check the correct receive input and the radio's USB/data audio and filter.
  2. Check Start and BW below the waterfall and the Hz scale above. They determine the displayed audio range.
  3. Use 2D and Digital's display options for the desired presentation. Make sure the complete Digital window has enough panel space; detach or maximize it if needed.
  4. Check RX level and avoid clipping. TX level controls transmit audio; set RF power on the radio.

On Mobile, RX/TX sliders are beside the waterfall and TX Hz is below it. The selected audio frequency is separate from the radio frequency in MHz. A message already prepared may retain its previous audio frequency until it finishes.

33 · Mobile contacts on the PC map and remote desktop

Completed mobile contacts reach the PC log through Cloud when both devices synchronize. In Map, select a data view that includes the logbook and remove band/mode filters hiding the contact. The map needs position information to place a station.

Live decodes on the PC map come from a connected digital radio/UDP source. Synchronizing a QSO through Cloud does not transfer Mobile's audio, waterfall or every decode. External reception reports, such as PSK Reporter, may arrive later; they show that a receiver reported the signal, not that a QSO was completed.

With Chrome Remote Desktop, choose a suitable resolution/scale in the remote session and rearrange panels if they become cramped. A larger local monitor cannot provide more detail than the remote PC's rendered resolution. HamNavigator should normally run as a standard user so remote control can operate its windows.
